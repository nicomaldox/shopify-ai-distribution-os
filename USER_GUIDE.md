# Shopify AI Distribution OS — Phase 1 User Guide

This guide provides a comprehensive, step-by-step walkthrough on how to configure, test, and use the entire flow of the Phase 1 Proof-of-Concept.

---

## 1. System Pre-requisites & Environment
Before using the flow, ensure your deployment is running.

1. **Access the VPS:** Ensure your Docker containers are running on your VPS (`181.215.135.249`).
2. **Ports to know:**
   - **Core API:** `http://181.215.135.249:8080` (Receives webhooks, generates AI, calculates ledger).
   - **Creator Studio:** `http://181.215.135.249:3000` (Where influencers see their earnings).
   - **Admin Console:** `http://181.215.135.249:3001` (Where you monitor the ledger and AI logs).

---

## 2. Setting Up Shopify Integration (The Commerce Layer)

To allow the system to attribute sales and refunds to creators, you must configure Shopify to send webhooks to your Core API.

### Step 2.1: Create a Custom App in Shopify
1. Log into your Shopify Admin dashboard.
2. Go to **Settings > Apps and sales channels > Develop apps**.
3. Click **Create an app** (Name it "Distribution OS Webhooks").
4. Under **Configuration > Admin API integration**, grant `read_orders` and `read_products` scopes.
5. Save and install the app. Under **API credentials**, copy the **API secret key** (this is your HMAC Secret).
6. *(Optional)* Add this secret to your VPS `.env` file under `SHOPIFY_WEBHOOK_SECRET` and restart the API so it can verify incoming signatures securely.

### Step 2.2: Configure Webhooks in Shopify
1. Go to **Settings > Notifications > Webhooks** (scroll to the bottom).
2. Click **Create webhook**.
3. Create the **Order creation** (or Order payment) webhook:
   - **Event:** `Order payment`
   - **Format:** `JSON`
   - **URL:** `http://181.215.135.249:8080/webhooks/shopify/orders/paid`
4. Create the **Refund creation** webhook:
   - **Event:** `Refund create`
   - **Format:** `JSON`
   - **URL:** `http://181.215.135.249:8080/webhooks/shopify/refunds/create`

## 3. Setting Up n8n (The AI Orchestration Layer)

The AI Director and Video Factory are orchestrated via an n8n workflow that you can host anywhere.

### Step 3.1: Import the Workflow
1. Open your self-hosted n8n instance.
2. Click **Add Workflow** > **Import from File**.
3. Select `workflows/n8n/Distribution_OS_Phase1.json` from this repository.

### Step 3.2: How the Workflow Functions
1. **Trigger:** The workflow starts with a generic Webhook node. You can trigger this from Shopify (e.g., when a new product is added) or manually via Postman.
2. **AI Director:** It extracts the `product_title` and `price` and makes a `POST` request to `http://181.215.135.249:8080/ai/generate-script`.
3. **Video Factory:** The Core API processes the AI script and automatically spawns background tasks to generate audio (OpenAI TTS) and video (Wan2.2), merging them with FFmpeg.

## 4. End-to-End Walkthrough: Fulfilling All Expected Functions

Now that the connections are made, here is how you test the entire pipeline end-to-end.

### Function 1: Generating AI Content (Director & Video Factory)
**Goal:** Generate a compliant marketing script and video for a product.
1. Open the Swagger UI at `http://181.215.135.249:8080/docs`.
2. Expand the `POST /ai/generate-script` endpoint and click **Try it out**.
3. Send a payload representing a new product:
   ```json
   {
     "product_id": "prod_123",
     "product_title": "AI Distribution OS Pro",
     "product_price": 3000
   }
   ```
4. **Expected Result:** The API returns a highly structured script generated by GPT-4o. The AI Middlewares will have automatically injected `#Ad` or `#Sponsored` tags to ensure compliance.
5. **Verify Telemetry:** Open the **Admin Console** (`:3001`) and navigate to the **Analytics** page. You will see the exact token usage, estimated cost, and latency for that specific GPT-4o call.

### Function 2: Real-Time Sales Attribution & Ledger (EARN)
**Goal:** Prove that when a customer buys a product using a creator's link/code, the creator gets paid.
1. Our seed data automatically provisioned a creator named **Alex The Tech Bro** with the discount code `ALEX10` at a 20% commission rate.
2. Go to your Shopify Storefront and add a product to the cart (e.g., total $1,000).
3. Proceed to checkout and apply the discount code `ALEX10`.
4. Pay for the order using the Shopify Bogus Gateway.
5. **Expected Result:** Shopify fires the webhook to your Core API. The Core API deduplicates the event, identifies the code `ALEX10`, attributes it to Alex, and writes an immutable `EARN` entry for $200 (20% of $1,000).
6. **Verify:** Open the **Creator Studio** (`:3000`) and navigate to the **Earnings** tab. You will see Alex's balance instantly increase by $200.

### Function 3: Proportional Refund Reversals (REVERSAL)
**Goal:** Prove that if a customer refunds an order, the system claws back the commission without destructively deleting database rows (financial compliance).
1. Go to your Shopify Admin Dashboard > **Orders**.
2. Select the order you just placed and click **Refund**.
3. Refund exactly half of the order (e.g., $500).
4. **Expected Result:** Shopify fires the refund webhook. The Core API calculates that 50% of the order was refunded, meaning 50% of the commission must be reversed. It writes an immutable `REVERSAL` entry for -$100.
5. **Verify:** Open the **Admin Console** (`:3001`) > **Ledger**. You will see the raw, double-entry accounting records: one positive `EARN` row, and one new negative `REVERSAL` row. The Creator's net balance adjusts automatically.

## 5. Security Defenses to Monitor
During normal usage, the OS acts defensively. Here is what is happening behind the scenes:
* **Webhook Duplication:** If Shopify accidentally fires the same order webhook twice (common on slow networks), the `webhook_inbox` table will catch the identical `X-Shopify-Webhook-Id` and drop the second request, preventing double-paying the creator.
* **SSRF Protection:** The Video Factory will automatically block any media URLs targeting local or private IP spaces (e.g., `127.0.0.1` or `169.254.169.254`) to prevent AWS/GCP metadata extraction attacks.
* **IP Privacy Hashing:** If you use the `/r/{slug}` redirect links, the system captures clicks but cryptographically hashes visitor IP addresses using a daily rotating `SESSION_SALT` to comply with GDPR.
